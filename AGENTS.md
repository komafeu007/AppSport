# AGENTS.md

Expo SDK 57 + React Native + TypeScript (strict) training app. Code and comments in English, but the product, UI copy, and specs are French ("AppSport Local").

## Do not trust your Expo training data

Expo ships breaking changes every SDK release. Before using any Expo/EAS/React Native API, check the installed version and read the versioned docs — do not answer from memory.

- SDK version lives in the `expo` dependency in `package.json` (currently `~57`).
- Versioned docs: https://docs.expo.dev/versions/v57.0.0/
- Full index with common-LLM-misconception corrections: https://docs.expo.dev/llms.txt

## Commands

This is an npm project (`package-lock.json`, no `bun.lock`) — use `npx`, not `bunx`.

```bash
npx expo install <package>   # always, instead of npm/yarn/bun add — resolves SDK-compatible versions
npx expo start               # dev server
npx tsc --noEmit             # typecheck — the only configured verification step
npx expo-doctor              # diagnose dependency/config problems
npx expo install --fix       # fix incompatible package versions
```

- No lint or test setup exists: no ESLint config, no test runner, no `lint`/`test` scripts. `npx expo lint` will prompt to install `eslint-config-expo` first — don't assume it works out of the box.
- Run `npx tsc --noEmit` before declaring any task done.

## Architecture

- Entrypoint: `index.ts` calls `registerRootComponent(App)`; the app lives in `App.tsx` (`package.json` `"main": "index.ts"`).
- Navigation is **React Navigation** (`@react-navigation/native` + `@react-navigation/native-stack` + `@react-navigation/bottom-tabs`), **not** Expo Router. À l'ouverture, tant qu'aucun compte n'est actif, la pile ne contient que le choix/création de profil (`Accounts` → `AccountForm`, cf. `AccountProvider`) ; un compte actif bascule sur la pile app. Bottom tabs (`src/navigation/BubbleTabBar.tsx` + `RootNavigator.tsx`): `Main` (accueil : la prochaine séance à démarrer + l'historique des séances terminées, chaque ligne ouvrant son récapitulatif) and `Seance` (séances, groupées par split). A root stack pushes `SessionEditor` (création/édition), `LiveWorkout` (séance en cours), `SessionSummary` (récapitulatif de fin de séance : volume, temps, reps, radar des muscles, courbe d'évolution, détail des exos — les graphiques sont en SVG via `react-native-svg`, inclus dans Expo Go), plus `Accounts` / `AccountForm` (gestion du profil). There is no `src/app/` route tree — do not add Expo Router or a file-based routes directory. There is **no standalone exercise-catalogue screen**: exercises are only browsed via the picker inside the session editor (`ExerciseSearchList`).
- Folders live under `src/`: `components/` (shared UI: `ExerciseSearchList`, `ActionSheet`, the exercise/plate sheets, and the `ui/` design-system primitives — all modals close on a tap outside, bottom sheets use `Sheet`), `domain/` (business rules, e.g. `workoutRules.ts`), `lib/` (pure helpers), `navigation/`, `screens/`, `services/`, `data/`, `theme/` (`colors.ts` + `tokens.ts`). Light app preferences use `expo-sqlite/kv-store` via `src/services/preferences.ts` (no schema change): active group, groups removed from the home page (`getHiddenGroupIds` / `setGroupHidden`, toggled from a group's « ⋯ » menu in the Séance tab — which also renames and deletes a group with `deleteSessionGroup`). The Profiles screen ends with a « Réinitialiser toutes les données » action (dev-friendly clean slate): `resetAppData()` wipes accounts/groups/programs/logs, `clearAllPreferences()` wipes the kv-store, and the exercise catalogue is kept.
- Rest alert: `src/services/restAlert.ts` wires a local notification (permission + Android channel `rest`) for the end of a rest, and the live screen plays `assets/sounds/rest-done.wav` with **expo-audio** when the app is in the foreground (the notification's own sound is muted in the foreground to avoid a double beep). **Two paths on purpose:** in the foreground the end of a rest is signalled by the beep *and* an **immediate** notification (`trigger: { channelId }`, the documented reliable path); the **deferred** notification (`TIME_INTERVAL`) is only scheduled when the app moves to the background (for the remaining seconds) and cancelled when it comes back — that is the only case where it is needed, since JS is suspended. A session ref invalidates schedules still in flight. Both `expo-audio` and `expo-notifications` ship in Expo Go; the `expo-audio` plugin is configured with the mic/background playback disabled (we only play a short beep). **Expo Go caveats (Android):** (1) `expo-notifications` imports its push-*topics* native module at load, which Expo Go does not bundle → the app crashed at startup with `Cannot find native module 'ExpoTopicSubscriptionModule'`; `metro.config.js` redirects that single import to the package's own stand-in (we never use topics) — remove the workaround once Expo Go bundles it or once we ship a development build (see expo/expo#49044); **restart the dev server (`npx expo start -c`) after editing `metro.config.js`**, Metro only reads it at startup. (2) `setNotificationChannelAsync` fails in Expo Go (`NullPointerException: … NotificationsChannelsProvider`) because its scoped channel provider is not registered — harmless: the native builder falls back to its own high-importance channel `expo_notifications_fallback_notification_channel` when the requested one is missing. The rest bar offers « −15 s », « Passer », « +15 s » and the countdown is derived from an end timestamp so it stays correct after a background round-trip.

## Data & domain

- `docs/CDC.md` — product spec (French, v2.0): dark high-contrast theme, palette `#121218` bg / `#00E676` accent / `#00B0FF` secondary / `#FF3D00` alert; rest-time and set rules keyed on `is_poly`; program-generation rules; 4 modules (Onboarding, Programme, Live Workout, Stats). Product source of truth — keep user-facing strings and domain terms in French.
- `docs/SCHEMA.sql` — SQLite schema source of truth: `ACCOUNTS`, `EXERCISES`, `SESSION_GROUPS`, `PROGRAMS`, `WORKOUT_EXOS`, `LOGS_SESSION`, `LOGS_SETS`. Persistence is SQLite via `expo-sqlite` (registered as a config plugin in `app.json`); keep the schema and this file in sync.
- `src/services/database.ts` — opens the DB, runs versioned migrations (`PRAGMA user_version`, currently **v10**) and seeds the exercise catalogue. Bump `DATABASE_VERSION` and add a migration branch for each change; any pre-v3 DB drops/recreates `EXERCISES`. Données **séparées par compte** : `SESSION_GROUPS`, `PROGRAMS` et `LOGS_SESSION` portent un `account_id`, et toutes les requêtes de liste filtrent dessus (le premier compte créé adopte les lignes `account_id IS NULL` créées avant les comptes). L'`ACCOUNTS` (profil Module 1 : prénom, âge, taille, poids, objectif, **niveau** (v10), zones douloureuses + note, fréquence/semaine, matériel, format et durée de séance) se gère via `src/services/account.tsx` (`AccountProvider` / `useAccount`) et `src/domain/profile.ts` (référentiel des choix). Séances are grouped in `SESSION_GROUPS` (splits like PPL/Maison) via `PROGRAMS.group_id`. `WORKOUT_EXOS` stores the rep range as `reps_min`/`reps_max` (double progression), one weight per set as JSON in `set_weights` (set 1 applies to all unless overridden), and `superset_group` (consecutive exercises sharing a non-null value are chained: no rest between them, rest only after the last). A finished workout is journalled by `saveWorkoutSession()` (LOGS_SESSION with `program_id` + LOGS_SETS per set). Weights are written back to `WORKOUT_EXOS` **across every session of the account** using the same exercise (`applyPlanWeights`), so loads stay in sync between workouts; `getLastSetsForExercise()` likewise looks at the last time the exercise was done in *any* session (the “previous” column). `SessionSummary` flags an exercise as a **record** when its best set of the session beats the best set ever logged for that exercise in earlier sessions (`getExerciseBestSetsBefore`, compared weight-first then reps via `beatsSet` — e.g. 15 kg × 6 beats 15 kg × 5); the live screen shows the current record to beat (`getExerciseBestSets`) and a **Record** badge once it's exceeded. Live workout: `rest_time` drives an actual rest countdown after a validated set (skipped between superset members), and finishing all sets of an exercise auto-scrolls to the next one.
- `src/data/exercises.seed.json` — 1 324 exercises imported from [hasaneyldrm/exercises-dataset](https://github.com/hasaneyldrm/exercises-dataset) (MIT). `SEED_EXERCISES` in the service wraps it.
- **Program generation** (`src/domain/programGenerator.ts`, pure engine + `src/services/programGeneration.ts` for DB glue + `src/screens/ProgramGeneratorScreen.tsx`): no AI and no API key — a rule engine over the 1 324-exercise catalogue. Inputs: objective, level, frequency, session duration, format, equipment, painful zones, recent exercise ids, seed. Tables: split templates (`FULL_BODY`, `PPL`, `UPPER_LOWER`, `MUSCLE_SPLIT`), per-objective volume/reps/rest (`OBJECTIVE_RULES`), `LEVEL_FACTOR`, and in `src/domain/exerciseCatalog.ts` the profile→dataset equipment mapping, `ZONE_GUARDS` (safety, not medical advice), `MUSCLE_PATTERNS` (expected movements per muscle), `isCompound` (fixes the dataset's `is_poly` heuristic), `isNonStrength`/`junkPenalty` (stretches, yoga, Olympic lifts, exotic entries) and `needsPullUpBar`. Scoring picks the main compound then isolation complements (except for biceps/triceps/calves/abs/forearms, where the first movement is an isolation), and `PATTERN_FAMILY` (in `exerciseCatalog.ts`) groups synonyms so a muscle never gets two exercises of the same **movement family** — no dumbbell bench press + incline press, and no lat pulldown + pull-up in the same group (the second is replaced by a row or a pullover). A soft session-wide family penalty keeps the angles different across the day, a slot can carry `prefer` (a Pull day wants rear delts, not an overhead press), growth additions are capped at one per group and scored as complements, and recently used exercises are penalized — `trimToDuration` then fits the target duration. Output = plan with rationale + warnings; the screen shows a preview with « Régénérer » (new seed) before « Enregistrer ». A generated program creates a **new group** with an 8-week block (`SESSION_GROUPS.bloc_debut`/`bloc_semaines`); when the block is due the Séance tab proposes a new one — always validated, never applied silently. Starting weights come from `getLastReferenceWeights` (last logged session per exercise).
  - **Derived fields, not from the source:** `nom_fr` is an auto-generated best-effort translation (the dataset ships English names + French *instructions* only), and `is_poly` comes from an isolation-keyword heuristic. Don't treat either as authoritative.
- `src/data/exerciseImages.ts` — generated map `filename → require()` for the 1 324 local 180×180 thumbnails in `assets/exercises/` (~12 MB, image © Gym visual). `EXERCISES.image` holds the filename key. Animated GIFs (122 MB) are **not** bundled and are currently not displayed anywhere (the old exercise-detail view was removed).
- `docs/TESTING.md` — how to run the app on a phone (Expo Go, dev build) and surface what works/fails.
- `src/theme/colors.ts` — official palette (`#121218` bg, `#00E676` accent, `#00B0FF` secondary, `#FF3D00` alert) plus derived neutrals. Use these instead of hard-coded colors.

## Rules

- **Every screen goes through the design system**: `src/theme/tokens.ts` (spacing, radius, typography, durations, spring) and `src/components/ui/` primitives. No hard-coded colors, radii or font sizes in screens; only the official palette from `src/theme/colors.ts`.
- Content modals are bottom sheets built on `src/components/ui/Sheet.tsx` (slide-in + spring, close on outside tap, close button, Android back). Confirmations and info dialogs use `src/components/ui/ConfirmSheet.tsx`, not `Alert.alert`. Animate with `Animated` (`Appear` for entrances, `PressableScale` for presses) — no animation library is installed.
- `ios/` and `android/` are gitignored and generated (Continuous Native Generation). Never create or hand-edit them — configure native behavior in `app.json` and config plugins.
- After adding any library with native code, the app needs a real build (`npx expo run:ios|android`, or EAS). EAS is configured via `eas.json`: the `preview` profile builds an **internal-distribution Android APK** (`distribution: internal` + `android.buildType: apk`) — the standalone install used on the phone at the gym, no dev server needed (`npx eas-cli@latest build --profile preview --platform android`; `android.package` = `com.komafeu.appsportlocal`). Run the CLI as `npx eas-cli@latest <command>`, not bare `eas`. Expo Go can never run without the dev server (it always fetches the JS bundle from Metro, tunnel or not).
- Prefer recommended Expo modules over third-party libraries before adding dependencies.
